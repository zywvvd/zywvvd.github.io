NAS 网关升级：公网入口单端口收敛
Yiwei Zhang 2026年11月14日 晚上
3.9k 字 33 分钟 0 次   0 人   0 条
1794661200000

本文最后更新于：2026年11月16日 下午

老 NAS 时代的公网访问是"一个服务一个口"：图床一个、评论一个、统计一个，连成一片的裸地址高位端口挂在域名下。这次虚拟化迁移把公网入口统一收进网关：全部 web 服务共享一个 HTTPS 端口，按 SNI 分发；外加几个各司其职的独立端口。本文讲收敛方案的原理与关键设计，是 NAS 架构升级 的网关篇。

升级前状态

老模式下公网访问是"一个服务一个口"，连成一片的高位端口挂在域名下。这个模式服役五年，问题不在哪个端口配错了，而在模式本身：

  • 暴露面大：每个端口都是扫描器的靶子，几十个端口意味着安全组、访问日志、证书分散在几十处，防守面铺得越开，越难盯
  • 证书散乱：旧方案靠第三方证书服务逐端口部署，续期链路脆弱——一次续期故障，全站 https 一起报错
  • 无备案的约束：家宽没有 ICP 备案，运营商会封 80/443，所有服务只能挂高位端口——端口越多，这个约束被放得越大

收敛方向也随之明确：

  • web 类服务：全部共享一个 HTTPS 端口，按子域名分发——暴露面从一个长列表收成一点，防守与规则都只需维护一处
  • 非 web 类：SSH、VPN 这类不走 HTTP 的，各自保留独立端口，各司其职

一句话：把"几十个口各站一个服务"改成"一个口按名字认各家服务"——服务并没有变少，变少的是被扫描、被维护、被续期的面。

SNI 分发原理

家宽没有 80/443，所以入口不能做成传统的"80 跳转 443"。方案是让全部 web 服务共享一个 HTTPS 高位端口，nginx 在 TLS 握手阶段工作：

关键在握手的最开头：客户端发起的 ClientHello 里带一个 SNI（Server Name Indication）字段——它指明"我要访问哪个域名"，在这个阶段还是明文，还没进入加密。nginx 读了这个字段就能提前决定把这个连接交给哪个后端；而加密协商在网关终结，后端全是纯 HTTP。所以实现比想象中简单，不用 stream 模块的 ssl_preread，直接用 http 层的 server_name 分发：

关键设计

证书自动化 —— 绕开 80/443 的续期。 收敛的前提是"一个端口承载全部子域名"，需要一张覆盖所有子域名的通配符证书，并且续期不能依赖任何被运营商封掉的端口。解法是 DNS-01 验证：

DNS-01 的验证记录由域名托管商的 API 自动增删，签出的证书覆盖全部子域名；续期由 acme.sh 自己的定时任务完成，续完自动 reload nginx。整个证书链路完全自治，第三方证书服务从架构里退役，一年两次的续期没人再操心。

续期的前提是泛解析。 一张通配证书 + 一条 * CNAME 顶掉过去十几个子域名的逐条配置——新子域名不需要任何 DNS 操作，天然落在证书与分发覆盖内。

兜底拒绝 —— 连 404 都不给。 最后一个 server 块 ssl_reject_handshake on 处理所有不认识的名字。扫描器拿伪造的 SNI 来探测时，拿到的是 TLS 握手层的拒绝，而不是 HTTP 的 404——404 好歹还说明"这里有个 web 服务"，握手拒绝则连这个信息都不暴露。

Host 头必须带端口。 proxy_set_header Host 要用 $http_host 而不是 $host——前者带端口、后者不带。评论系统的服务端配置里，前端就是靠这个值拼出正确的 API 地址；写成 $host，前端会把请求打到不存在的默认 443 上干等超时。这类"差一个变量就全站超时"的坑，配置时最容易漏。

独立端口 —— 各有各的非 HTTP 理由。 几个不走 SNI 的端口不是漏网，而是各有一个理由：

  • 代码仓 SSH：git 走 SSH 协议，不是 HTTP，独立端口直通内置 SSH 服务，只认公钥、无密码可爆，客户端配一条就是 GitHub 体验
  • 开发机 SSH：远程开发的直达通道
  • WireGuard：回国代理，走 UDP。人在外面连上隧道，家里整个内网（后台、面板、文件服务）全部直达，零新增暴露面

WireGuard 用 wg-easy 容器跑在网关上，这里踩过一个值得记的映射坑：新版把端口配置应用到了容器内 wireguard 的实际监听口，而映射还写的旧默认口——结果入站 UDP 全部送到一个没人监听的端口，静默丢弃。客户端只发包不收包、服务端零字节收到，排查半天。修复就是让映射两端端口号一致，一次握手就通。

配置规模

收敛后的网关配置呈一个可预期的形状：

    P --> S2["server_name 子域名B → 应用虚拟机"]

新增一个 web 服务的全部动作，就是加一个 server 块。

实施与结果

收敛完成后，暴露面缩水九成——从一长列独立端口变为「一个 HTTPS 入口 + 少数独立端口」；新增服务只需加一个 server 块；证书续期一年两自动；家庭内外无差别访问。

验收做了两条：

  • 对外：从外部网络逐个子域名 curl，全部返回预期状态码
  • hairpin 回流：在家内网里用公网域名访问，流量从路由器出去再折返回来，全部子域名实测可达——hairpin 通了，家里家外用同一套地址，配置零分歧

尾声

从一长列端口到极简暴露面，删掉的不只是路由器里的转发规则，还有每次上新的心智负担：现在加一个服务，就是在网关加一个 server 块、DNS 加一条泛解析已覆盖的记录，完了。
