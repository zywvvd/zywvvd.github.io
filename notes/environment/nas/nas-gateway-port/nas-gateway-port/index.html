NAS 网关收敛：三十个公网端口变四个
Yiwei Zhang 2026年11月14日 晚上
2.7k 字 23 分钟 0 次   0 人   0 条
1794661200000

本文最后更新于：2026年11月14日 上午

老 NAS 时代的公网暴露面是三十多个转发端口，uipv4.zywvvd.com:33030 到 33060 连成一片，每个服务一个口。这次虚拟化迁移把公网入口统一收敛到网关虚拟机的 nginx 上：一个 HTTPS 端口按 SNI 分发全部 web 服务，外加三个各司其职的独立端口，总共四个。本文记录收敛方案、通配符证书与 WireGuard 回国代理的完整配置。

为什么要收敛

三十多个端口的问题不只是难记：

  • 暴露面大：每个端口都是扫描器的靶子，安全组、证书、日志分散在三十多个地方
  • 证书散乱：旧方案靠第三方证书服务逐端口部署，续期链路脆弱，一次故障全站 https 报错
  • 无备案的约束：家宽没有 ICP 备案，运营商封 80/443，所有服务只能挂高位端口，端口越多个性越强

收敛的前提是 DNS 与证书问题的解法：域名在百度云解析，通配符证书走 DNS-01 验证——acme.sh 原生支持百度云 DNS 插件，用 AccessKey 自动添加验证记录签发 *.zywvvd.com，不依赖任何 80/443 端口，续期全自动。家宽 IP 由 DDNS 每十分钟刷新一次 A 记录，配合泛解析一条 * CNAME 顶掉过去十几个子域名的逐条配置。

SNI 分发原理

家宽没有 80/443，所以入口不能做成传统的"80 跳转 443"。方案是让全部 web 服务共享一个高位端口（61213），nginx 在 TLS 握手阶段读取 ClientHello 里的 SNI（Server Name Indication）字段——这个字段在加密握手的最开始明文传输，nginx 据此把 img.zywvvd.com 路由到图床、waline.zywvvd.com 路由到评论系统，一个端口承载全部子域名。

nginx 的实现比想象中简单，因为后端全是纯 HTTP，TLS 在网关终结，直接用 http 层的 server_name 分发，不需要上 stream 模块的 ssl_preread：

两个细节值得记。一是 proxy_set_header Host 必须用 $http_host 而不是 $host——前者带端口后者不带，评论系统的服务端靠它拼出正确的 API 地址，丢了端口前端就会把请求打到不存在的 443 上干等超时。二是最后一个拒绝握手的兜底 server 块，扫描器随便伪造 SNI 探测时拿到的是 TLS 层的拒绝，连 HTTP 404 都不给。

DNS-01 的验证记录由百度云 API 自动增删，签出的 ECC 证书覆盖全部子域名，acme.sh 自己的定时任务负责续期，续完自动 reload nginx。第三方证书服务从架构里彻底退役。

独立端口与 WireGuard

三个不走的 SNI 的端口各有理由：

  • 49512 → 代码仓 SSH：git 走 SSH 协议不是 HTTP，独立端口转发到 OneDev 内置的 SSH 服务，只认公钥无密码可爆，客户端 ~/.ssh/config 配一条就是 GitHub 体验
  • 63197 → 开发机 SSH：远程开发的直达通道
  • 51128/UDP → WireGuard：回国代理

WireGuard 用 wg-easy 容器跑在网关上，人在外面时手机或电脑连上隧道，家里整个内网（网关后台、监控面板、文件服务）全部直达，零新增暴露面。这里踩过一个映射坑记录一下：wg-easy 新版把 WG_PORT 应用到了容器内 wireguard 的实际监听口，而 compose 映射还写的旧默认口，结果入站 UDP 全部送到一个没人监听的端口上静默丢弃——客户端只发包不收包、服务端零字节收到。修复就是让映射两端端口号一致（51128:51128/udp），一次握手就通了。

验证

收敛完成的验收两条：一是外部网络逐个子域名 curl 全部返回预期状态码；二是 hairpin 回流——在家内网里用公网域名访问，流量从路由器出去再折返回网关，全部子域名实测可达。hairpin 通了，家里家外用同一套地址，配置零分歧。

尾声

从三十多个端口到四个，删掉的不只是路由器里的转发规则，还有每次上新的心智负担：现在加一个服务，就是在网关加一个 server 块、DNS 加一条泛解析已覆盖的记录，完了。
