基于 PVE 的 NAS 架构升级
Yiwei Zhang 2026年11月14日 晚上
4.7k 字 40 分钟 0 次   0 人   0 条
1794659400000

本文最后更新于：2026年11月16日 晚上

用了五年的 NAS 到了该升级的时候：原有平台的计算、内存、存储接口与系统盘都已逼近瓶颈。这次的方向，是把「一台机器承担所有职责」重构为「一台主机运行八台虚拟机、按职责分层」——全部服务在不停机的状态下完成迁移，并同步升级到各软件当前最新版本。本文是 NAS 硬件升级方案 的收官记录：为什么这么改、怎么想清楚、怎么落地，不展开操作细节。

升级前状态

老 NAS 是 2021 年装的，用了五年，问题不在某一处，而在每一层都到了瓶颈：

  • 计算：低功耗处理器（J3455，四核四线程），单核性能弱，还扛着虚拟化层 + 存储系统 + 容器编排的整套叠加，博客服务一忙，CPU 排队直接拖累全家响应
  • 内存：加起来 12GB，跑两个虚拟机就见底——虚拟机的开销是「基础占用 + 按需增长」，余量不足时只能靠换服务取舍，别无他法
  • 存储与接口：几个原生口加转接加 USB 凑出的盘位已经是物理极限，六块机械盘加两块固态塞满；机械盘组还长期跑在小带宽的转接链路上，备份这类大流量任务一直是慢速段
  • 系统盘：装在 USB 盘上，长期运行存在连接稳定性与供电的隐患——系统盘是根基，这块短板五年没敢彻底解决
  • 架构：所有服务挤在一个系统里，升任何一个组件都要掂量全局；网络、数据库端口、反向代理互相缠绕，动一处牵全身，五年攒下的技术债欠到拆不动

升级方向也明确了两条：

  • 硬件上，处理器换到主流桌面平台、内存翻倍、系统盘改走固态，机械盘作为数据盘后续整体搬迁——不买显卡，需要算力的活走外部接口，不为一年用不了几次的能力付钱
  • 架构上，放弃「一台机器干所有事」，改走虚拟化分层——这是下面全部内容的核心

一句话：瓶颈不只是「跑不动」，而是「动一处要掂量全局」。 前者换硬件就能解，后者得换架构。这次两条都动。

目的

方向定了还不够，得立成可验收的靶子。新平台四条目的：

  • 性能余量：跑全部现有服务绰绰有余，未来扩展有地方放
  • 故障隔离：博客挂了不影响家人相册，存储维护不用停应用——服务之间不再共享同一个故障域
  • 系统盘质变：从悬在 USB 盘上的心里刺，变成带校验和的固态镜像
  • 整机可维护：任何一台「虚拟的服务器」都能单独备份、回滚、重建

结尾「当前效果」一节会逐条回来对账。

PVE 是什么

方案的地基是一个叫 Proxmox VE（下称 PVE）的开源服务器虚拟化平台：基于 Debian，把 KVM/QEMU 全虚拟化与 LXC 容器两种技术收进一个 Web 管理面。说人话，它是一台物理机上「再开多台独立小机器」的管家：

它有几个让我最顺手的能力：

  • 职责分离：一台虚拟机只干一件事，存储归存储、应用归应用、网关归网关。单点故障被限制在单台虚拟机的边界内，不会像以前那样「一个组件挂了全家陪着」
  • 镜像与克隆：搭好一台底座模板，几十秒克隆出一台同款虚拟机——同类服务的重复系统搭建，一次成型
  • 快照与回滚：操作前打一个存储级快照，出岔子一键退回——虚拟化层替应用层兜底，改坏了大不了重来
  • 在线调整：CPU、内存等资源在虚拟机运行时就能热调整、立即生效，不用停机等窗口
  • 存储弹性：能直接对接 ZFS 这类文件系统，借它的校验和、快照与 RAID 能力做底层冗余；备份也不是靠「复制文件夹」，而是整机级快照
  • 开源生态：免费、社区活跃、脚本工具齐全，单机起步，将来要组集群、做高可用也有平滑路径

一句话概括优势：把「一台机器干所有事」的强耦合，拆成「每件事一台独立虚拟机」的解耦——想动哪台就动哪台，想升级谁就升级谁，边界清清楚楚。

为什么不是继续裸机 Docker

其实还有一条更省事的路摆在桌面上过：继续裸机，全部服务塞进 Docker。不选的理由恰恰藏在它「简单直接」的表象里——所有服务仍然共享同一个故障域，网络与系统配置照样互相缠绕，这正是旧平台五年乱象的源头。PVE 多一层抽象，换来的是按职责切分的能力与独立的备份/回滚/重建粒度；约 5% 的性能开销加内存预分配，对新平台的余量来说不值一提。

硬件随之定版：CPU 用 9700X，性能够用、发热不高；虚拟化层存储用两块固态组 ZFS mirror——校验和加镜像双保险，对「虚拟机磁盘，坏了就是灾难」的数据，比普通 RAID 更合适；六块机械盘原地不动，等整体搬迁批次。

实施方案

新主机切成八台虚拟机，按职责各管一摊，VMID 与内网地址尾号一致——「110 就是点 110」。每一层的划分都有一个具体动机：

职责 干什么 为什么单独拆
存储层 管文件服务，机械盘搬入后接管全部文件 磁盘 I/O 是最容易互相干扰的资源，给它独立故障域，别的服务卡顿不拖它
应用层 博客全家桶：图床、评论、统计、一言等容器 全部对外服务的宿主，独立便于发布、扩容、排障
网关层 统一对外入口 + 回国代理 公网暴露面集中在这里，防守面收成一点，规则也只需维护一处
观测层 拨测、指标采集、面板展示 观测要独立于被观测对象，否则「看门人自己也躺在火场里」
家庭层 网盘 + 家庭相册 数据资产与个人数据单独成层，备份、迁移、权限都好定向处理
开发层 开发机，远程直达 开发环境变更频繁，给它独立空间，折腾坏成本最低
支撑层 按需启动的图形排障机 平时不占资源，需要时随开随用，隔离宿主机图形依赖
模板 克隆即用的底座副本 保证所有虚拟机出身一致，避免「每台机器都是手工搭的野路子」

分层之外立了几条纪律：

  • 存储分级：热数据与数据库放固态虚拟盘，大文件与冷数据归机械盘——快慢分置，各取其长
  • 指令集对齐：虚拟机 CPU 显式指定现代指令集级别——默认的保守档位缺新指令，新版数据库会直接崩，这是全家克隆后统一补的一道课
  • 磁盘真实释放：虚拟机磁盘配了让删除空间能真还给宿主机的配置，配合定期整理，虚拟盘不会「只涨不缩」
  • 快照纪律：动系统前先打快照，验证没问题再收；异常从不硬修，先回滚再看
  • 备份要验真：收官核查时发现备份任务从未真正自动跑过——调度器曾挂死，「任务已建」掩盖了「从未执行」；宁可承认没备份，不要假装有备份
  • 入口收敛：对外只保留统一的按名字分发入口，不把一串端口裸露到公网，暴露面收掉一截

实施过程

先给物理机本身排雷。 PVE 9.2 安装一次成，但点亮后三天崩了四次：先怀疑主板，换一块无效；最后逐槽轮换内存定位——内存颗粒与这代平台不兼容，换品牌后彻底稳定。这一案留下的排查优先级：新平台连续异常，先怀疑内存兼容性，比换主板便宜得多。

迁移最大的风险是「搬家当天全站停摆」。这次把风险按三步拆散：

旧机器不停。 老的应用先把数据盘切到备份组上继续跑，拔掉系统盘都无感知。新机器逐台搭建，搭好一台、验证一台、入口改向一台——出问题改回入口就是回滚，单个服务的回退窗口压到秒级。

数据全程带对账。 每一项迁移都做数量级核对：评论一千多条逐条对齐、访问统计几十万事件百分百落位、网盘文件连密码哈希一起搬、家庭相册几套库全量核对。中间还补过一个统计缺口——新旧切换时间差里产生的数据，跨版本手工合并回新库。

对账的意义不只是「数字对上」，更是给「旧机可以拆」提供一个可验证的依据——每一个服务迁完，对账通过，旧机才敢少一样东西。

迁移即升级。 不搬旧版本，直接上新版：评论、统计、数据库、写作框架全部跳过中间版本升到当前最新。五年欠的版本账一次还清，旧版本里的已知问题在新版本里天然是「已修复」。

一个习惯值得单说：动公网相关配置前，先验证线上引用再删记录。 迁移中清过一批多年没人碰的解析记录，其中一条差点误删仍在用的线上服务——事后定下纪律，删除类操作一律先验证引用、再动手。

当前效果

收官时把全栈版本过了一遍：存储、网关、观测、博客、数据这些层用的都是各家当前最新可用版，只留一个最早的历史组件排进了下个窗口。监控与告警覆盖到虚拟机、服务、底层硬件与对外链路，公开健康页做了脱敏——访客看得见健康状态，看不见内网细节。

服务已全部切到新的子域名，旧入口地址整体废弃；博客侧上万处引用批量换到新域名后做了专项验证，生产页面上旧机器的引用清零——旧机器现在哪怕直接断电，博客不受一点影响。

工程侧沉淀了两样长效资产：

  • 配置仓库化：服务配置各自成仓集中托管，数据与密钥排除在外，每日自动快照比对漂移——任何机器炸了，都能从仓库完整重建
  • 发布流程一键化：过去多步手工操作收敛成一条命令，构建、索引、同步、部署一步到位

确认迁完的旧服务已经全部停机，旧系统重负全部卸掉。老机器上刻意保留三类：

  • 还没迁真实数据的小服务
  • 备份链
  • 公网入口的命脉

都排在机械盘搬家批次里，搬完拔电入库。

开篇的四条目的，收官逐条对账：

  • 性能余量：全部服务迁入后资源占用远低于容量；真出现瓶颈还能在线扩——应用虚拟机一次 OOM 后，内存在线翻倍，分钟级搞定
  • 故障隔离：后续迁移中应用虚拟机反复重建配置，家人服务零感知——隔离真实生效
  • 系统盘质变：固态镜像加校验和，定期 scrub 相当于主动体检
  • 整机可维护：八台虚拟机纳入统一快照策略，配置全部进仓

四条全落地。地基打完最大的变化：后面所有的迁移和折腾都变成了「虚拟机里的事」——炸了重建、小了扩容、闲了关机，物理机退回它该在的位置：稳定跑着，别的不管。

尾声

五年前攒第一台时，图的是「一台机器解决所有需求」；五年后拆成八台虚拟机，图的是「每个需求都能单独折腾」。老机器教会我什么都能跑，新平台教会我跑坏了怎么救——前者是省心，后者是放手。这大概是这次升级真正买到的东西。
